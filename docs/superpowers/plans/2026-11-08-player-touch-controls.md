# แผนเพิ่มปุ่มควบคุมแบบแตะที่มุมขวาบนของ /player

สถานะ: ผู้ใช้อนุมัติให้พัฒนาแล้ว ดำเนินการและตรวจสอบตามบันทึกท้ายเอกสาร

## ปัญหาและตำแหน่งที่ผู้ใช้เลือก

แถบ `Home เล่นซ้ำ • End จบเพลง • ↑↓ ดูเพลงในคิว • F11 เต็มจอ/ลดจอ`
ใน `src/app/player/page.tsx` เป็น `<kbd>` และ `<span>` ไม่มี click handler
และใช้ `hidden ... sm:flex` จึงไม่แสดงบนจอแคบ การแตะข้อความจึงไม่เรียกคำสั่งเล่นเพลง

ผู้ใช้เลือกให้ใช้ตำแหน่งขวาบนที่วงใน browser comment และแทนที่แถบเดิม
ข้อเสนอคือไอคอน 4 ปุ่มเรียงแนวนอน ใช้พื้นหลังดำโปร่งและเส้นขอบบาง
ไอคอน 18–20px แต่พื้นที่แตะอย่างน้อย 44×44px

## พฤติกรรมที่เสนอ

| ปุ่ม | คำสั่ง | รายละเอียด |
| --- | --- | --- |
| RotateCcw | เล่นซ้ำ | เรียก restartCurrentSong ของเพลงปัจจุบัน เช่นเดียวกับ Home |
| SkipForward | จบเพลง | ใช้ skipSong เช่นเดียวกับ End: จบเพลงปัจจุบันแล้วไปเพลงถัดไปตามระบบคิวเดิม |
| ListMusic | เพลงในคิว | เปิด/ปิด queue browser เดิม เลือกเพลงด้วยการแตะ และมีปุ่มปิดในหัวรายการ |
| Maximize2 / Minimize2 | เต็มจอ / ออกจากเต็มจอ | ใช้สถานะและความสามารถจริงของเบราว์เซอร์ ไม่จำลองการกด F11 |

ทุกปุ่มมี aria-label และ title ที่อธิบายคำสั่ง ปุ่มคิวมี aria-expanded/aria-controls
ปุ่มเต็มจอเปลี่ยนไอคอนและชื่อเมื่อสถานะเปลี่ยน มี focus ring สำหรับคีย์บอร์ด
ปุ่มเล่นซ้ำ/จบเพลงปิดใช้งานเมื่อไม่มีเพลง และป้องกันการกดจบเพลงซ้ำขณะคำสั่งเดิมกำลังทำงาน
ความล้มเหลวต้องแจ้งในหน้าและปลดสถานะ busy ให้ลองใหม่ได้

## รูปแบบหน้าจอ

- แทนที่แถบคำแนะนำเดิมด้วยแถบปุ่มจริงที่ขวาบน ใช้ได้ทั้งแตะ เมาส์ และคีย์บอร์ด
- เก็บปุ่ม QR Code แยกอยู่ด้านขวาของแถบ และไม่เปลี่ยนพฤติกรรมเลือก Karaoke/MV
- บนจอแคบที่แถวเดียวไม่พอ ให้แถบควบคุมย้ายลงแถวถัดไปโดยยังจัดชิดขวา
  ไม่ลดพื้นที่แตะเพื่อยัดให้พอดี
- ใช้พื้นที่ส่วนหัวร่วมกันกับช่องค้นหา: ปรับจุดเริ่มของ search overlay ให้ต่ำกว่าส่วนหัว
  เพื่อไม่ให้แถบปุ่มทับช่องกรอกหรือปุ่มปิดค้นหาเมื่อหัวหน้ามีสองแถว
- เผื่อ safe-area ของจอแนวตั้งและแนวนอน ทดสอบความกว้าง 320, 390, 691 และ 1280px
- ปุ่มคิวยังต้องปิดคิวได้เมื่อ queue browser เปิดอยู่ พร้อมปุ่มปิดที่หัวรายการสำหรับมือถือ
- เมื่อเปิด QR/lyrics modal ให้ชั้น dialog รับการแตะตามปกติ ไม่ให้ toolbar ลอยรับ click ทะลุ modal
- การแตะคำสั่งควบคุมต้องไม่ focus ช่องกรอก และไม่ทำให้คีย์บอร์ดมือถือเด้งกลับ

## ข้อจำกัดเรื่องเต็มจอ

`F11` เป็นปุ่มของเบราว์เซอร์ จึงใช้การส่ง KeyboardEvent จำลองเพื่อแทนการแตะไม่ได้
วางคำสั่ง Fullscreen API ใน handler ของการแตะโดยตรง และใช้ pageRef ของหน้า Player
เพื่อให้แถบควบคุมและรายการคิวยังอยู่ใน fullscreen element เดียวกัน

- ถ้ารองรับ requestFullscreen และ fullscreenEnabled ให้เปิด native fullscreen
  และสลับออกด้วย exitFullscreen
- ฟัง fullscreenchange เพื่ออัปเดตปุ่มเมื่อผู้ใช้กด Back/Escape หรือเบราว์เซอร์ออกเต็มจอเอง
- หากไม่รองรับ API ให้เสนอ “ขยายเวที” ภายในพื้นที่หน้าเว็บแทน และเรียกโหมดนี้ให้ชัดเจน
  การขยายในหน้าเว็บไม่สามารถรับประกันการซ่อนแถบที่อยู่หรือแถบระบบของโทรศัพท์
- ถ้าเบราว์เซอร์ปฏิเสธคำขอที่รองรับอยู่แล้ว ให้แสดงข้อความและลองใหม่ได้
- รักษาการจัดการ orientation และเจ้าของ fullscreen เดิม โดยไม่สั่งออกจาก fullscreen
  ของ element อื่นและไม่อ้างว่าการหมุนเครื่องหรือขยายหน้าเท่ากับ native fullscreen

อ้างอิง: https://developer.mozilla.org/en-US/docs/Web/API/Element/requestFullscreen

## แนวทางเชื่อมโค้ด

1. สร้าง `src/components/PlayerQuickControls.tsx` เป็นส่วนแสดงปุ่มที่รับ callbacks,
   สถานะคิว, สถานะเต็มจอ และ disabled/busy ผ่าน props ไม่สร้างระบบคิวหรือ player ชุดใหม่
2. ปรับ `src/app/player/page.tsx` ให้แทนแถบเดิมด้วย component นี้ และจัดส่วนหัวแบบ responsive
   ใช้ restartCurrentSong เดิมและ skipSong ของ KaraokeContext
3. เปิดช่องทางเรียก toggleQueueBrowser แบบมีชนิดข้อมูลชัดเจนจาก page ไปยัง
   PlayerSearchOverlay เช่น imperative handle ตามรูปแบบที่โปรเจ็กต์ใช้กับ YouTubePlayer
   เก็บ state ของคิวใน Overlay ต่อไป และใช้ onQueueBrowserActiveChange เดิมส่งสถานะกลับ page
4. หากเปิดคิวขณะค้นหา ให้ปิด/ยกเลิกงานค้นหาเดิมก่อนแล้วเปิดคิวด้วย handler เดิม
   ไม่ใช้การ dispatch ปุ่มลูกศรหรือ Enter จำลอง
5. ปรับ PlayerSearchOverlay ให้มีปุ่มปิดคิวที่แตะได้ โดยใช้ closeQueueBrowser เดิม
   และรักษาการ blur/ไม่คืนโฟกัสบนมือถือจากงานก่อนหน้า
6. รวมการเข้า/ออกเต็มจอของหน้าไว้ที่ handler เดียว รวมความหมายของปุ่มและข้อความผิดพลาด
   ป้องกัน state ของ fullscreen ที่หน้าและ player ขัดกัน
7. ให้ปุ่มลัด Home/End/ลูกศรเดิมเรียกคำสั่งร่วมกันกับปุ่มแตะ และปล่อย browser F11 เดิมทำงานตามปกติ

## เกณฑ์ผ่าน

ผู้ใช้โทรศัพท์แตะเล่นซ้ำ จบเพลง เปิด/ปิดคิว และเปลี่ยนโหมดแสดงผลได้โดยไม่ต้องมีคีย์บอร์ดจริง
แถบใหม่ใช้ตำแหน่งขวาบนแทนแถบเดิม ปุ่มไม่ชนส่วนหัวอื่น ไม่มีคีย์บอร์ดเด้งจากการแตะ
และยังมีทางออกจากคิว/เต็มจอหรือโหมดขยายเวทีเสมอ


## บันทึกการดำเนินการ

- แทนแถบคำแนะนำเดิมด้วย PlayerQuickControls เชื่อมคำสั่งร่วมกับคีย์ลัด และใช้ imperative handle เปิด/ปิดคิวเดิม
- จบเพลงมี synchronous pending guard ร่วมกันทั้งการแตะและปุ่ม End พร้อมแสดงข้อผิดพลาดและลองใหม่ได้
- Fullscreen ใช้ stage ทั้งหน้าเป็นเป้าหมาย มี pending guard และ fallback ที่ใช้ชื่อขยายเวทีอย่างชัดเจน
- ผลการตรวจอิสระพบสองกรณี: portal ของ Google เปลี่ยนที่จน widget หาย และคิวเปิดไม่ได้ระหว่างดาวน์โหลดคลัง ทั้งสองมี regression tests ที่เห็น fail ก่อนแก้และ pass หลังแก้
- ใช้ portal host คงที่ภายใน stage ตลอดอายุหน้าต่างเนื้อเพลง และให้คิวที่ผู้ใช้เปิดมีลำดับเหนือ panel ดาวน์โหลดโดยไม่ยกเลิกดาวน์โหลด
- ชุดทดสอบรวม 157 รายการผ่าน รวม focused tests 29 รายการ; production build และ targeted ESLint ผ่าน
- ตรวจเบราว์เซอร์จริงที่ความกว้าง 320/390/691/1280 และแนวนอน 844x390: ปุ่ม 44x44, ไม่มี horizontal overflow หรือทับส่วนเลือกประเภทเพลง/ช่องค้นหา ตรวจเปิด/ปิดคิวและ native fullscreen เข้า/ออกแล้ว
- ยังไม่มีผลทดสอบบนโทรศัพท์ iPhone/Android เครื่องจริง; การตรวจจอมือถือเป็นการปรับ viewport และทดสอบ focus ด้วย browser/component mocks
